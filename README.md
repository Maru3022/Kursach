# Крестики-нолики — курсовой проект C++17

Цветное настольное приложение на C++17 и raylib: быстрая игра, отдельные серии и динамический турнир Single Elimination на 8 участников. Каждый участник может быть человеком либо компьютерным соперником лёгкого, среднего или сложного уровня. Победители серий автоматически переходят из четвертьфиналов в полуфиналы и финал.

## Возможности

- два человека или любая комбинация человека и компьютера;
- лёгкий уровень (случайный ход), средний (фиксированные правила), сложный (Minimax);
- выбор участника с символом X в быстрой игре, X всегда ходит первым;
- серии до 3, 5 или 7 побед с отдельным счётом ничьих;
- турнир до 1, 3 или 5 побед в каждом противостоянии;
- 7 живых карточек сетки, соединительные линии, цветовые состояния и чемпион;
- автоматические матчи двух компьютерных соперников с видимой задержкой без блокировки интерфейса;
- сохранение статистики и полного состояния турнира;
- русский интерфейс и включённый шрифт DejaVu Sans.

## Запуск в CLion

1. Открыть корневую папку как CMake-проект.
2. Выбрать профиль `Release` или `Debug` и цель `TicTacToe`.
3. Дождаться загрузки закреплённого raylib 5.5 через FetchContent.
4. Запустить цель. Рабочей папкой должна быть папка с EXE; CMake автоматически копирует `assets` рядом.

Для тестов запустить цель `game_tests` либо `ctest --test-dir <папка-сборки> -C Release --output-on-failure`.

## Сборка Windows EXE

```powershell
cmake -S . -B build -DBUILD_GAME=ON
cmake --build build --config Release
cmake --install build --config Release --prefix dist
```

Готовая переносимая структура: `dist/TicTacToe.exe`, `dist/assets/fonts/DejaVuSans.ttf`, `dist/README.txt`. Для MSVC используется статическая C/C++ runtime; raylib также собирается статически. Системные Windows/OpenGL библиотеки уже входят в Windows.

Для переноса скопировать всю папку `dist`, не только EXE. CLion на другом компьютере не нужен. Проверка на физически другом компьютере всё равно рекомендуется.

Сохранения находятся в `%LOCALAPPDATA%/TicTacToe`: `statistics.txt` и `tournament.txt`.

## Алгоритмы выбора хода компьютерного соперника

Лёгкий уровень собирает свободные клетки и случайно выбирает одну из них. Средний строго применяет правила: победа, блокировка, создание и защита от вилок, центр, противоположный угол, угол и сторона. Он не использует полный перебор и остаётся потенциально победимым. Сложный уровень использует полный Minimax: перебирает продолжения партии и выбирает ход с лучшим гарантированным результатом. Поэтому при корректных правилах он играет оптимально и не проигрывает.

Все решения вычисляются локально средствами C++17. Приложению не нужен интернет; оно не выполняет HTTP-запросов и не использует API, нейросети, машинное обучение или обучаемые модели. Minimax традиционно относится к алгоритмам игрового ИИ, но здесь это автономный математический поиск по дереву состояний, а не нейросеть или генеративная модель.

| Уровень | Метод | Особенность |
|---|---|---|
| Лёгкий | Случайный выбор | Может пропускать победы и угрозы |
| Средний | Расширенные фиксированные правила | Видит победы, угрозы, вилки и позиционные приоритеты |
| Сложный | Minimax | Исследует все допустимые продолжения |
